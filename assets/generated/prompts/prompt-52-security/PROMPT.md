# NEXORA — Production prompt 52: Security & Access Control Props

## Mission
Create original, production-ready NEXORA assets for security and access control. Keep every output isolated to this prompt folder.

## Scope
Fictional access-control objects for homes, factories, laboratories, and game facilities: card readers, fictional biometric readers, access keypads, stylized security cameras, sensors, barriers, turnstiles, gates, alarm panels, and facility monitoring modules.

## Before generation
Read this prompt and relevant art-direction/pipeline documentation. Inspect current assets and manifests. Enumerate missing assets, variants, stable IDs, counts, and dimensions. Do not duplicate existing assets; explicit source requirements take precedence.

## Image-generation protocol
- Create original NEXORA designs; never copy, trace, extract, or closely reconstruct third-party game assets, mods, brands, or artwork.
- Identify each output type: texture, tileable material, icon, sprite, or isolated prop.
- Follow exact source dimensions. Required 16×16 textures must be natively 16×16.
- Maintain clear silhouettes, controlled pixel clusters, coherent voxel/pixel-art styling, readable contrast, and consistent scale.
- No accidental blur, unwanted anti-aliasing, photorealism, unrelated scenery, watermark, logo, or unrequested text. Use transparency only when appropriate.
- Tileable textures must pass a repeated 3×3 seam check. Isolate each prop/icon and keep framing consistent.
- Inspect at native size and enlarged nearest-neighbor scale. Validate dimensions, format, alpha, readability, silhouette, duplicates, filenames, and requirements; regenerate failures.
- Contact sheets are previews only and never replace individual production files.
- Record only verifiable metadata; use `unknown` when tool/model/date is unavailable. Never claim an image was generated, saved, or validated unless the actual file exists and the action occurred.

## Output contract
Save final images only in `assets/generated/prompts/prompt-52-security/images/`. Use stable lowercase filenames. Maintain `manifest.json` in that folder with asset ID, filename, source prompt, tool/model/date when known, dimensions, format, version, status, originality review, and validation results. Version approved assets rather than overwriting them.

## Completion report
Report requested/generated/accepted/rejected counts, exact paths, validation performed, gaps, and blockers. Separate verified facts from recommendations.
